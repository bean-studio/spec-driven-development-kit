# Feature Brief: Feature Name

## Objective

State the user or operator outcome and its upstream product basis.

## Users And Scenarios

Identify affected users and the scenarios this feature supports.

## Scope

List included behavior.

## Exclusions

List intentionally excluded behavior and deferred work.

## Product And UX Decisions

Record feature-level decisions and cite their upstream sources.

## Backend Contract

Define entities, state transitions, API or event shapes, validation, errors,
permissions, persistence, and background work owned by this feature. Reference
cross-cutting architecture instead of redefining it.

## Frontend Contract

Define screens, states, interactions, accessibility, responsive behavior, and
error or empty states owned by this feature.

## Verification

Map risks and hard rules to focused automated or manual checks.

## Acceptance / Done

- [ ] Each measurable acceptance criterion is stated independently.
- [ ] Backend Contract and Acceptance / Done remain aligned.
- [ ] Required documentation and release impact are identified.

## Open Questions

  - **Owner:** authoritative document or decision maker
  - **Decision:** complete only after approval; cite the decision source

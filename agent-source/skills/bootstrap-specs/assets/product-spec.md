# Product Specification: Product Name

This document is the authority for intended product behavior. Statements here
outrank code; code that contradicts an explicit clause is drift.

## Purpose

State the problem the product solves and the outcome that defines success.

## Users

Identify each user or operator role and what it needs from the product.

## Scope

List the capabilities the product provides. For an adopted existing codebase,
mark each entry as **intended** (a decision) or **observed** (recorded current
behavior awaiting confirmation).

## Non-Goals

List capabilities deliberately excluded, with the reason when it prevents
repeated debate.

## Behavior

Organize by capability area. For each area, state the intended behavior
precisely enough that an implementation can be judged conforming or drifted.
Record feature-level detail in feature contracts and link them here rather
than duplicating.

## Cross-Cutting Product Rules

Record product rules that span capability areas: permissions, auditability,
data retention, terminology, and similar.
